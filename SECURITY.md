# Security

Report vulnerabilities privately to abdullahfawad.dev@gmail.com. Do not include production evidence or credentials in public issues.

Authenticated HTTP mutations verify Supabase Auth and the database command verifies current membership, role, tenant, station and transition authority. Authenticated clients can also invoke exposed RPCs directly, so SQL is the authoritative boundary. Recipient onboarding verifies the signed-in, confirmed email and explicit invitation choice before creating membership. Driver reporting uses a separate expiring bearer capability. Public API keys confer no owner privileges. There is no service-role key in the application runtime.

Business tables have RLS and no authenticated direct-write grants. Private security-definer functions use fixed search paths and operation-specific authority. The kiosk projection excludes prices, balances, stock volumes, calibration charts, and reconciliation results. Evidence objects are private, append-only and limited to image MIME types and 5 MB; storage policies permit authorized staff upload into their own actor/tenant path, and owner evidence review uses short-lived signed URLs. Browser-supplied MIME, GPS and capture metadata are not independent attestations.

The staged `20261109115526_secure_domain_boundaries.sql` migration validates parsed numeric values and JSON numeric snapshots inside SQL and adds finite-value persistence constraints. It stops on existing invalid values rather than repairing financial or inventory data silently. It adds expiring, recipient-selected invitation acceptance/decline, preserving existing membership and revocation. Apply and verify this migration before releasing the corresponding onboarding UI. Local tests do not prove it has been applied to a hosted project.

Security limitations: browser camera/location values are evidence, not trusted hardware attestations. Web clients can be modified. Human review, certified calibration and operational controls remain required. The amount privacy toggle masks presentation only; it is not an authorization boundary. Configure production SMTP, MFA policy, backup retention, incident monitoring and recovery drills before a business-critical rollout.

Prefer small reviewed pull requests. Dependabot proposes upgrades; CI validates changes before release. Never expose privileged tokens to pull request code.

The offline terminal persists only encrypted context/drafts and non-secret version, actor/workspace identifiers and KDF metadata. It derives a nonextractable AES-GCM key using PBKDF2-SHA256 (600,000 iterations), random salt/IVs and actor/workspace/record authenticated data. A session-generation lease invalidates pending work on Lock, sign-out, identity change and unmount; network abortion is supplemented by checks after IndexedDB/crypto awaits. By default the key stays in memory. Explicit trusted-device access additionally persists a nonextractable CryptoKey for at most24hours in IndexedDB; this reduces at-rest protection on a compromised/unlocked device. The account password is never persisted. Expiry, Lock and logout revoke future automatic restoration. This does not defend an unlocked compromised browser or same-origin script injection. Use a strong separate passphrase and a managed device. Browser storage eviction can destroy unsynced records.

New-account enrollment and password recovery require 15–128 Unicode code points; existing sign-in credentials are not normalized or silently changed. The local Auth configuration is staged at the same minimum. Hosted SMTP, leaked-password protection and MFA policy must be verified separately. Dashboard layout storage contains only versioned panel identifiers and ordering, scoped to actor/workspace/station; the amount privacy switch masks presentation and is not authorization.

Offline replay checks active membership, tenant/station, the original open shift, a 24-hour capture window, photo ownership and current financial limits. Stable request IDs and payload hashes reject conflicting replays. Original capture time and offline provenance remain visible to owners. No offline draft is a credit authorisation. The service worker caches a public shell and allowlisted static assets only, never private API responses or signed-in pages.

Driver links are bearer capabilities: share only with the intended driver, expire after 48 hours and can be revoked. The server stores token hashes and accepts reports only while a delivery is dispatched. Location, capture times and browser hashes remain client assertions, not hardware attestation.
